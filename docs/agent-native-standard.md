# Agent-Native Standard

Standard version: `0.7.0` (see `agent/standard-version.toml`).

Keep product truth in Rust, SQL, and generated contracts. Agents must not add Python except for rare dated advanced-ML/data exceptions under `python/ai-service`. Route every path to an owner and proof lane.

## Navigation

Before editing any file, read in order:

1. `agent/owner-map.json` — maps every path prefix to an owner group.
2. `agent/proof-lanes.toml` — maps each lane name to its `just` command.
3. `agent/test-map.json` — maps crate/module prefixes to their test commands.
4. `agent/generated-zones.toml` — lists paths that are generated; never hand-edit these.
5. `agent/boundaries.toml` — declares domain, web, Python, and queue boundaries.

## Architecture Summary

Jansu is a stateless Apache Kafka-compatible broker in Rust. The binary has
subcommands: `broker` (default), `cat`, `topic`, `generator`, `perf`, `proxy`.

Key crate responsibilities:

| Crate | Role |
|---|---|
| `jansu-broker` | Kafka API broker, generic over Coordinator + Storage |
| `jansu-sans-io` | Code-generated Kafka wire protocol |
| `jansu-service` | TCP service layers (rama) |
| `jansu-storage` | Storage backends: PostgreSQL, libSQL, S3, memory |
| `jansu-schema` | Schema registry + Iceberg/Delta lake integration |
| `jansu-client` | Async Kafka protocol client |

Storage backends are selected by feature flag and dispatched via `StorageContainer`.

## Boundaries

- `agent/boundaries.toml` is the authoritative boundary manifest.
- Rust domain logic lives under `crates/domain` paths; forbidden imports are listed there.
- Generated contract paths: `contracts/generated`.
- Python is only allowed under `python/ai-service`, under a dated exception.
- Queue adapters must not import raw broker clients directly.

## Generated Zones

- `agent/generated-zones.toml` lists the generated paths.
- `agent/repo-score.json` and `agent/repo-score.md` are generated by `jankurai audit`.
- `jansu-sans-io/src/` contains code generated from `jansu-sans-io/message/*.json`; do not hand-edit.

## Proof Lanes

Run `just fast` for the deterministic local proof lane (fmt + clippy + unit tests).
Run `just score` to regenerate the jankurai audit artifacts.
Run `just security` for the secret and dependency scan lane.
Run `just db-doctor` to validate the DB surface and copy the destructive-delete proof artifact.
Run `just tool-adoption-evidence` to generate all tool-adoption receipt files.

Full lane definitions: `agent/proof-lanes.toml`.

## Audit Rules

- `agent/audit-policy.toml` declares minimum score (85) and fail-on severities.
- `agent/security-policy.toml` declares the secret and dependency policy.
- Hard caps from the last audit run are listed in `agent/repo-score.md`.
- The repair queue is at `target/jankurai/repair-queue.jsonl` after `just score`.

## Test Routing

- `agent/test-map.json` maps prefixes to the narrowest runnable test command.
- Integration tests require `just ci` (starts Docker services).
- Unit and doc tests run without external services: `just fast-unit`, `just fast-doc`.

## Exception Pattern

All exceptions require a dated, owner-signed record in `docs/exceptions/`.
No open-ended exceptions are permitted.

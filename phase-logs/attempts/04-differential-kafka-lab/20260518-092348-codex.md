## Outcome

- Root cause: the differential lab ran Rust tests in parallel while every
  Docker-managed Kafka instance used the same Compose project, container name,
  and default port.
- Fix: Docker-managed Kafka now uses a unique Compose project, container name,
  and free localhost port per test unless `JANSU_DIFF_KAFKA_BOOTSTRAP` supplies
  an external broker.
- Retry hardening: when an auto-port Docker startup fails, the retry now
  allocates a fresh Compose project, container name, and port. A fixed
  `JANSU_DIFF_KAFKA_PORT` is reused only when the caller explicitly supplied it.
- Produce setup now creates the Jansu topic explicitly via the broker
  CreateTopics route before using librdkafka, mirroring the Kafka AdminClient
  topic setup.
- Dougx was left without Kafka Docker/runtime additions; its existing cutover
  guard already scans dependency trees for `rdkafka`/`kafka` runtime crates.
- The compatibility contract parser now strips Markdown code ticks from
  structured log file bullets before checking paths, matching the existing
  phase-log style.

## Residual Risks

- If `JANSU_DIFF_KAFKA_PORT` is manually forced, callers must run the external
  differential tests serially or provide unique ports themselves.

## Next Recommended Action

- Keep the GitHub Actions command parallel by default; use
  `JANSU_DIFF_KAFKA_BOOTSTRAP` only when testing all workloads against one
  intentionally shared external Kafka broker.

## What Phase 08 must finish

Phase 08 is explicitly about **exact Fetch, ListOffsets, and OffsetForLeaderEpoch semantics**, including timestamp lookups, log start offsets, high watermark, last stable offset, leader epoch history/fencing, and not advertising API 23 until semantics are verified. The phase doc also says not to fake epoch/history, not to advertise unsupported fetch versions, and not to return empty success for fencing/unknown/offset errors. ([GitHub][1])

The current ledger says Phase 08 is in progress and that the remaining broker ListOffsets failures are specifically mixed-partition and produced-epoch wire failures with KafkaProtocol overflow / `UnexpectedEof`. ([GitHub][2])

The most important finding: **Phase 08 is not just missing tests; the current ListOffsets response assembly is structurally unsafe.** It rebuilds the response from storage output rather than preserving request shape, sorts topics through a `BTreeSet`, drops partitions that storage did not return, and emits `old_style_offsets(None)` even though ListOffsets v0 requires an offsets array. The Kafka protocol defines ListOffsets v0 response partition entries as `partition error_code [offsets]`, while v1+ uses `timestamp offset`; v4+ adds `leader_epoch`. ([GitHub][3])

That explains the wire failures: when the broker emits a response whose shape does not exactly match the request/version schema, Java/KafkaProtocol decoding can overflow or hit `UnexpectedEof`.

# Phase 08 completion plan

## 1. Fix ListOffsets response shape first

### Current defect

`jansu-storage/src/service/list_offsets.rs` currently:

1. Converts requested partitions into a flat storage request.
2. Calls `ctx.state().list_offsets(...)`.
3. Builds topics from a `BTreeSet` of topic names found in storage responses.
4. Builds partition responses from storage responses only.
5. Sets `old_style_offsets(None)`.
6. Uses current leader epoch for returned offsets rather than epoch-at-offset.

That is incompatible with Kafka response-shape requirements. Kafka clients expect one response entry for each requested topic/partition slot, in request order, with fields appropriate for the requested API version. ([Apache Kafka][4])

### Required behavior

For every `ListOffsetsRequest`:

| Case                                             | Required response                                                                                         |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| Known topic/partition, valid timestamp           | One partition response, `error_code = NONE`, offset/timestamp filled                                      |
| Unknown topic or partition                       | One partition response, `UNKNOWN_TOPIC_OR_PARTITION`, offset `-1`, timestamp `-1`, v0 offsets array empty |
| Requested `current_leader_epoch < current`       | `FENCED_LEADER_EPOCH`                                                                                     |
| Requested `current_leader_epoch > current`       | `UNKNOWN_LEADER_EPOCH`                                                                                    |
| Requested `current_leader_epoch == -1` or absent | No fencing                                                                                                |
| v0 response                                      | `old_style_offsets = Some(vec![offset])` on success, `Some(vec![])` on error                              |
| v1+ response                                     | timestamp/offset populated by version-gated codec                                                         |
| v4+ response                                     | `leader_epoch` is the epoch active at the returned offset                                                 |

Kafka’s ListOffsets request docs define `current_leader_epoch` fencing: larger than current returns `UNKNOWN_LEADER_EPOCH`, smaller than current returns `FENCED_LEADER_EPOCH`. ([Apache Kafka][5])

## 2. Add leader epoch helper functions

Patch `jansu-storage/src/service/leader_epoch.rs`.

The current helper only returns sorted history, current epoch, and `-1` fallback. ([GitHub][6]) Add two missing pieces: epoch-at-offset and consistent fencing.

```rust
use jansu_sans_io::ErrorCode;
use rama::Context;

use crate::{LeaderEpochRecord, Result, Storage, Topition};

pub(crate) async fn leader_epoch_history<G>(
    ctx: &Context<G>,
    topition: &Topition,
) -> Result<Vec<LeaderEpochRecord>>
where
    G: Storage,
{
    let mut history = ctx.state().leader_epoch_history(topition).await?;
    history.sort_unstable();
    Ok(history)
}

pub(crate) fn current_leader_epoch(history: &[LeaderEpochRecord]) -> Option<LeaderEpochRecord> {
    history.last().copied()
}

pub(crate) fn leader_epoch_or_unknown(history: &[LeaderEpochRecord]) -> i32 {
    current_leader_epoch(history).map_or(-1, |record| record.epoch)
}

/// Return the leader epoch that was active for `offset`.
///
/// Kafka ListOffsets v4+ includes the leader epoch associated with the
/// returned offset. That is not always the current epoch.
pub(crate) fn leader_epoch_for_offset(history: &[LeaderEpochRecord], offset: i64) -> i32 {
    if history.is_empty() {
        return -1;
    }

    history
        .iter()
        .rev()
        .find(|record| record.start_offset <= offset)
        .or_else(|| history.first())
        .map_or(-1, |record| record.epoch)
}

/// Apply Kafka current_leader_epoch fencing semantics.
///
/// - -1 / absent means no fencing.
/// - lower than current => FENCED_LEADER_EPOCH.
/// - higher than current => UNKNOWN_LEADER_EPOCH.
/// - equal => OK.
pub(crate) fn current_leader_epoch_error(
    requested: Option<i32>,
    history: &[LeaderEpochRecord],
) -> Option<ErrorCode> {
    let requested = requested?;

    if requested == -1 {
        return None;
    }

    let Some(current) = current_leader_epoch(history) else {
        return Some(ErrorCode::UnknownLeaderEpoch);
    };

    if requested < current.epoch {
        Some(ErrorCode::FencedLeaderEpoch)
    } else if requested > current.epoch {
        Some(ErrorCode::UnknownLeaderEpoch)
    } else {
        None
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn leader_epoch_for_offset_picks_epoch_active_at_offset() {
        let history = [
            LeaderEpochRecord {
                epoch: 0,
                start_offset: 0,
            },
            LeaderEpochRecord {
                epoch: 1,
                start_offset: 10,
            },
            LeaderEpochRecord {
                epoch: 2,
                start_offset: 20,
            },
        ];

        assert_eq!(0, leader_epoch_for_offset(&history, 0));
        assert_eq!(0, leader_epoch_for_offset(&history, 9));
        assert_eq!(1, leader_epoch_for_offset(&history, 10));
        assert_eq!(1, leader_epoch_for_offset(&history, 19));
        assert_eq!(2, leader_epoch_for_offset(&history, 20));
        assert_eq!(2, leader_epoch_for_offset(&history, 21));
    }

    #[test]
    fn leader_epoch_for_offset_returns_unknown_without_history() {
        assert_eq!(-1, leader_epoch_for_offset(&[], 0));
    }

    #[test]
    fn current_leader_epoch_error_matches_kafka_fencing() {
        let history = [LeaderEpochRecord {
            epoch: 4,
            start_offset: 0,
        }];

        assert_eq!(
            Some(ErrorCode::FencedLeaderEpoch),
            current_leader_epoch_error(Some(3), &history)
        );
        assert_eq!(None, current_leader_epoch_error(Some(4), &history));
        assert_eq!(
            Some(ErrorCode::UnknownLeaderEpoch),

        assert_eq!(None, current_leader_epoch_error(Some(-1), &history));

    }
```

## 3. Replace ListOffsets service assembly

Patch `jansu-storage/src/service/list_offsets.rs`.

This version builds a response skeleton from the original request, validates leader epoch fencing before storage lookup, preserves topic/partition order, fills every requested partition, and emits the v0 offsets array.

```rust
use std::{
    collections::{BTreeMap, VecDeque},
    ops::Deref as _,
};

use jansu_sans_io::{
    ApiKey, ErrorCode, IsolationLevel, ListOffset, ListOffsetsRequest, ListOffsetsResponse,
    list_offsets_response::{ListOffsetsPartitionResponse, ListOffsetsTopicResponse},
};
use rama::{Context, Service};
use tracing::{debug, error, instrument};

use super::leader_epoch::{
    current_leader_epoch_error, leader_epoch_for_offset, leader_epoch_history,
};
use crate::{Error, LeaderEpochRecord, ListOffsetResponse, Result, Storage, Topition};

#[derive(Clone, Copy, Debug, Default, Eq, Hash, Ord, PartialEq, PartialOrd)]
pub struct ListOffsetsService;

impl ApiKey for ListOffsetsService {
    const KEY: i16 = ListOffsetsRequest::KEY;
}

#[derive(Debug)]
struct PendingListOffset {
    topic_slot: usize,
    partition_slot: usize,
    topition: Topition,
    request: ListOffset,
}

fn partition_error(
    partition_index: i32,
    error_code: ErrorCode,
) -> ListOffsetsPartitionResponse {
    ListOffsetsPartitionResponse::default()
        .partition_index(partition_index)
        .error_code(error_code.into())
        .old_style_offsets(Some(Vec::new()))
        .timestamp(Some(-1))
        .offset(Some(-1))
        .leader_epoch(Some(-1))
}

fn partition_response(
    topition: &Topition,
    offset: &ListOffsetResponse,
    history: &[LeaderEpochRecord],
) -> Result<ListOffsetsPartitionResponse> {
    let error_code = offset.error_code();
    let listed_offset = offset.offset();

    let leader_epoch = if error_code == ErrorCode::None {
        listed_offset
            .map(|offset| leader_epoch_for_offset(history, offset))
            .unwrap_or(-1)
    } else {
        -1
    };

    let old_style_offsets = match (error_code, listed_offset) {
        (ErrorCode::None, Some(offset)) => vec![offset],
        _ => Vec::new(),
    };

    Ok(ListOffsetsPartitionResponse::default()
        .partition_index(topition.partition())
        .error_code(error_code.into())
        .old_style_offsets(Some(old_style_offsets))
        .timestamp(offset.timestamp()?.or(Some(-1)))
        .offset(listed_offset.or(Some(-1)))
        .leader_epoch(Some(leader_epoch)))
}

impl<G> Service<G, ListOffsetsRequest> for ListOffsetsService
where
    G: Storage,
{
    type Response = ListOffsetsResponse;
    type Error = Error;

    #[instrument(skip(ctx, req))]
    async fn serve(
        &self,
        ctx: Context<G>,
        req: ListOffsetsRequest,
    ) -> Result<ListOffsetsResponse> {
        let throttle_time_ms = Some(0);

        let isolation_level = req
            .isolation_level
            .map_or(Ok(IsolationLevel::ReadUncommitted), |isolation_level| {
                IsolationLevel::try_from(isolation_level)
            })?;

        let topics = if let Some(request_topics) = req.topics {
            let mut response_topics: Vec<(
                String,
                Vec<(i32, Option<ListOffsetsPartitionResponse>)>,
            )> = Vec::with_capacity(request_topics.len());

            let mut pending = Vec::new();
            let mut histories: BTreeMap<Topition, Vec<LeaderEpochRecord>> = BTreeMap::new();

            for request_topic in request_topics {
                let topic_slot = response_topics.len();
                let topic_name = request_topic.name;
                let request_partitions = request_topic.partitions.unwrap_or_default();

                let mut partition_slots: Vec<_> = request_partitions
                    .iter()
                    .map(|partition| (partition.partition_index, None))
                    .collect();

                for (partition_slot, partition) in request_partitions.iter().enumerate() {
                    let topition = Topition::new(
                        topic_name.clone(),
                        partition.partition_index,
                    );

                    let history = match leader_epoch_history(&ctx, &topition).await {
                        Ok(history) => history,
                        Err(Error::Api(ErrorCode::UnknownTopicOrPartition)) => {
                            partition_slots[partition_slot].1 = Some(partition_error(
                                partition.partition_index,
                                ErrorCode::UnknownTopicOrPartition,
                            ));
                            continue;
                        }
                        Err(err) => return Err(err),
                    };

                    if let Some(error_code) =
                        current_leader_epoch_error(partition.current_leader_epoch, &history)
                    {
                        partition_slots[partition_slot].1 = Some(partition_error(
                            partition.partition_index,
                            error_code,
                        ));
                        continue;
                    }

                    let request = ListOffset::try_from(partition.timestamp)?;

                    histories.insert(topition.clone(), history);
                    pending.push(PendingListOffset {
                        topic_slot,
                        partition_slot,
                        topition,
                        request,
                    });
                }

                response_topics.push((topic_name, partition_slots));
            }

            let storage_requests: Vec<_> = pending
                .iter()
                .map(|pending| (pending.topition.clone(), pending.request))
                .collect();

            let storage_responses = ctx
                .state()
                .list_offsets(isolation_level, storage_requests.deref())
                .await
                .inspect(|responses| debug!(?responses, ?storage_requests))
                .inspect_err(|err| error!(?err, ?storage_requests))?;

            let mut by_topition: BTreeMap<Topition, VecDeque<ListOffsetResponse>> =
                BTreeMap::new();

            for (topition, response) in storage_responses {
                by_topition.entry(topition).or_default().push_back(response);
            }

            for pending in pending {
                let response = match by_topition
                    .get_mut(&pending.topition)
                    .and_then(VecDeque::pop_front)
                {
                    Some(offset) => {
                        let history = histories
                            .get(&pending.topition)
                            .map(Vec::as_slice)
                            .unwrap_or_default();

                        partition_response(&pending.topition, &offset, history)?
                    }
                    None => partition_error(
                        pending.topition.partition(),
                        ErrorCode::UnknownTopicOrPartition,
                    ),
                };

                response_topics[pending.topic_slot].1[pending.partition_slot].1 = Some(response);
            }

            Some(
                response_topics
                    .into_iter()
                    .map(|(name, partitions)| {
                        let partitions = partitions
                            .into_iter()
                            .map(|(partition_index, response)| {
                                response.unwrap_or_else(|| {
                                    partition_error(
                                        partition_index,
                                        ErrorCode::UnknownTopicOrPartition,
                                    )
                                })
                            })
                            .collect();

                        ListOffsetsTopicResponse::default()
                            .name(name)
                            .partitions(Some(partitions))
                    })
                    .collect(),
            )
        } else {
            None
        };

        Ok(ListOffsetsResponse::default()
            .throttle_time_ms(throttle_time_ms)
            .topics(topics))
        .inspect(|response| debug!(?response))
    }
}
```

```rust

```

## 4. Lock storage-side ListOffsets contract

The storage trait already exposes `fetch`, `offset_stage`, `list_offsets`, `offset_for_leader_epoch`, and `leader_epoch_history`; `OffsetStage` carries log start, high watermark, and last stable offset. ([GitHub][7]) Phase 08 should make the following contract explicit across all storage engines:

```rust
/// For each requested topition, return exactly one response in input order.
///
/// Unknown topic/partition may be represented either as:
/// - an explicit ListOffsetResponse with UNKNOWN_TOPIC_OR_PARTITION, or
/// - omitted only if the service layer fills the error response.
///
/// Prefer explicit one-for-one responses in storage implementations.
async fn list_offsets(
    &self,
    isolation_level: IsolationLevel,
    offsets: &[(Topition, ListOffset)],
) -> Result<Vec<(Topition, ListOffsetResponse)>>;
```

For every storage engine:

1. `ListOffset::Earliest` returns `offset_stage.log_start()`.
2. `ListOffset::Latest` returns:

   * high watermark/log end for `ReadUncommitted`;
   * last stable offset for `ReadCommitted`.
3. Timestamp lookup returns the first batch offset whose timestamp is greater than or equal to requested timestamp.
4. Timestamp before first record returns first visible offset.
5. Timestamp after last record returns `-1` or Kafka-equivalent no-offset response, depending on the existing generated `ListOffsetResponse` contract.
6. Unknown topic/partition must not return empty success.
7. Leader epoch history must not silently default to empty for initialized partitions.

The default `leader_epoch_history` currently returns an empty vector in the trait. ([GitHub][7]) That is acceptable only as a trait fallback, not as Phase 08 behavior for active storage engines. Each engine participating in Phase 08 should initialize:

```rust
LeaderEpochRecord {
    epoch: 0,
    start_offset: 0,
}
```

when a partition is created.

## 5. Fix Fetch exactness

The Fetch service already applies leader-epoch fencing and returns high watermark, log start, and last stable offset fields. ([GitHub][8]) The gaps to close for Phase 08 are:

1. Respect per-partition `partition_max_bytes`.
2. Stop long-polling once `min_bytes` is satisfied.
3. Avoid sleeping when `max_wait_ms == 0`.
4. Ensure error partitions are returned, not dropped.
5. Ensure read-committed fetch uses LSO visibility rules.
6. Ensure leader epoch fencing uses the same helper as ListOffsets and OFLE.

Patch shape for `jansu-storage/src/service/fetch.rs`:

```rust
fn partition_budget(global_remaining: u32, requested: Option<i32>) -> u32 {
    requested
        .and_then(|value| u32::try_from(value).ok())
        .filter(|value| *value > 0)
        .map_or(global_remaining, |value| value.min(global_remaining))
}
```

Inside `fetch_partition`, before calling storage:

```rust
let mut partition_max_bytes =
    partition_budget(*max_bytes, fetch_partition.partition_max_bytes);

if partition_max_bytes == 0 {
    return Ok(None);
}
```

Then call storage with the partition cap:

```rust
let frames = ctx
    .state()
    .fetch(
        &topition,
        fetch_partition.fetch_offset,
        min_bytes.min(partition_max_bytes),
        partition_max_bytes,
        isolation_level,
    )
    .await?;
```

After building the fetched record set:

```rust
let used = u32::try_from(fetched.byte_size())?;
*max_bytes = max_bytes.saturating_sub(used);
partition_max_bytes = partition_max_bytes.saturating_sub(used);
```

For the outer long-poll loop, change the loop to break immediately once enough bytes are available:

```rust
loop {
    responses.clear();

    for fetch_topic in fetch_topics.iter() {
        // existing per-topic / per-partition assembly
    }

    bytes = u32::try_from(responses.byte_size())?;

    if bytes >= min_bytes || max_wait.is_zero() || start.elapsed() >= max_wait {
        break;
    }

    let remaining = max_wait.saturating_sub(start.elapsed());
    let sleep_for = remaining.min(Duration::from_millis(250));

    if sleep_for.is_zero() {
        break;
    }

    tokio::time::sleep(sleep_for).await;
}
```

This does not yet implement Kafka’s “first non-empty batch may exceed max bytes” nuance unless storage already does that internally. Add a test for it and document the behavior. Do not advertise Fetch versions whose first-batch semantics are not proven.

## 6. Keep API 23 unadvertised until proof, but add route version safety

The broker currently advertises only ApiVersions and Metadata, while storage routes include Fetch, ListOffsets, OffsetForLeaderEpoch, Produce, and others. ([GitHub][9]) The service route layer currently version-checks only API keys present in the advertised map. That means routed-but-unadvertised APIs can bypass version-range checks. ([GitHub][10])

Fix this without advertising API 23 prematurely.

Patch `jansu-service/src/api.rs` conceptually like this:

```rust
#[derive(Clone, Debug, Default)]
pub struct FrameRouteService<State, E> {
    routes: Arc<BTreeMap<i16, BoxService<Frame, Frame, E>>>,
    advertised_versions: Arc<BTreeMap<i16, ApiVersionRange>>,
    supported_versions: Arc<BTreeMap<i16, ApiVersionRange>>,
    _state: PhantomData<State>,
}
```

In the builder, compute supported route versions from `RootMessageMeta` for every route:

```rust
impl<State, E> FrameRouteBuilder<State, E> {
    fn route_supported_versions(&self) -> BTreeMap<i16, ApiVersionRange> {
        self.routes
            .keys()
            .filter_map(|api_key| {
                RootMessageMeta::try_from(*api_key).ok().map(|meta| {
                    (
                        *api_key,
                        ApiVersionRange {
                            min_version: meta.min_version(),
                            max_version: meta.max_version(),
                        },
                    )
                })
            })
            .collect()
    }

    pub fn build(self) -> Result<FrameRouteService<State, E>, Error> {
        let supported_versions = self.route_supported_versions();

        let advertised_versions = self
            .advertised_versions
            .clone()
            .unwrap_or_else(|| supported_versions.clone());

        Ok(FrameRouteService {
            routes: Arc::new(self.routes),
            advertised_versions: Arc::new(advertised_versions),
            supported_versions: Arc::new(supported_versions),
            _state: PhantomData,
        })
    }
}
```

Then in `serve`, check supported versions, not advertised versions:

```rust
if let Some(version_range) = self.supported_versions.get(&api_key) {
    if api_version < version_range.min_version || api_version > version_range.max_version {
        return unsupported_version_response_frame(
            &req,
            api_key,
            api_version,
            correlation_id,
            tag_buffer,
            version_range,
        );
    }
}
```

This preserves the project rule: **routed is not advertised**. AGENTS.md explicitly says not to claim an API is supported just because it is routed, and not to advertise compatibility without ledger-backed proof. ([GitHub][11])

## 7. OffsetForLeaderEpoch requirements

`OffsetForLeaderEpochService` is already routed but intentionally unadvertised; its source comment says API 23 must not be advertised until leader-epoch history semantics are fully verified. ([GitHub][12]) The service should remain unadvertised until the following are true across storage engines and broker wire tests:

| Request epoch                            | Required result                          |
| ---------------------------------------- | ---------------------------------------- |
| Epoch older than current and known       | End offset = next epoch’s `start_offset` |
| Epoch equal current                      | End offset = high watermark/log end      |
| Epoch greater than current               | `UNKNOWN_LEADER_EPOCH`, end offset `-1`  |
| Current leader epoch lower than current  | `FENCED_LEADER_EPOCH`                    |
| Current leader epoch higher than current | `UNKNOWN_LEADER_EPOCH`                   |
| Unknown partition                        | `UNKNOWN_TOPIC_OR_PARTITION`             |

API 23 request fields include `current_leader_epoch`, and Kafka’s protocol docs define the same fencing rule. ([Apache Kafka][4])

No advertisement change should happen until the differential/client harness produces proof. The compatibility ledger currently records API 23 as routed, unadvertised, and partial. ([GitHub][13])

# Differential Kafka lab requirement

Phase 08 cannot be called fully finished for a Kafka replacement unless Phase 04/AUDIT-012 has at least a minimal differential harness. AUDIT says multiple compatibility claims are blocked because the Kafka/client differential harness is not stable. ([GitHub][14])

For Phase 08, the minimal differential matrix is:

| Scenario                                 |                             Kafka result | Jansu result |
| ---------------------------------------- | ---------------------------------------: | -----------: |
| Empty partition earliest                 |                                        0 |   must match |
| Empty partition latest                   |                                        0 |   must match |
| Produced records earliest                |                                log start |   must match |
| Produced records latest read-uncommitted |                   high watermark/log end |   must match |
| Timestamp before first record            |                             first offset |   must match |
| Timestamp in middle                      | first offset with timestamp >= requested |   must match |
| Timestamp after last record              |                         no-offset result |   must match |
| Mixed known/unknown partitions           |     one response per requested partition |   must match |
| Low `current_leader_epoch`               |                    `FENCED_LEADER_EPOCH` |   must match |
| High `current_leader_epoch`              |                   `UNKNOWN_LEADER_EPOCH` |   must match |
| OFLE old epoch                           |                  next epoch start offset |   must match |
| OFLE current epoch                       |                   high watermark/log end |   must match |
| OFLE future epoch                        |                   `UNKNOWN_LEADER_EPOCH` |   must match |

# API advertisement rules after fixes

The compatibility docs say the ledger is the source of truth and that no API is fully supported unless the ledger has proof. ([GitHub][15]) The current compatibility ledger shows Fetch and ListOffsets routed but unadvertised/uncertified, and API 23 routed but unadvertised/partial. ([GitHub][13])

So the correct sequence is:

1. Implement fixes.
2. Pass storage and broker wire tests.
3. Pass differential Kafka/client lab.
4. Update phase log attempt with exact commands/results.
5. Update `docs/compatibility/ledger/generated-request-apis.json`.
6. Only then update broker `advertised_versions()`.

Patch shape after proof:

```rust
fn advertised_versions() -> impl IntoIterator<Item = (i16, ApiVersionRange)> {
    [
        (
            ApiVersionsRequest::KEY,
            ApiVersionRange {
                min_version: 0,
                max_version: 4,
            },
        ),
        (
            MetadataRequest::KEY,
            ApiVersionRange {
                min_version: 12,
                max_version: 12,
            },
        ),
        (
            FetchRequest::KEY,
            ApiVersionRange {
                min_version: 0,
                max_version: FETCH_MAX_VERIFIED,
            },
        ),
        (
            ListOffsetsRequest::KEY,
            ApiVersionRange {
                min_version: 0,
                max_version: LIST_OFFSETS_MAX_VERIFIED,
            },
        ),
        (
            OffsetForLeaderEpochRequest::KEY,
            ApiVersionRange {
                min_version: 0,
                max_version: OFFSET_FOR_LEADER_EPOCH_MAX_VERIFIED,
            },
        ),
    ]
}
```

Use the highest versions actually proven by broker wire + client differential tests. Do not guess the max version.

# Definition of complete for Phase 08

Phase 08 is finished only when all of these are true:

1. **ListOffsets broker wire tests no longer produce overflow or `UnexpectedEof`.**
2. **ListOffsets preserves request shape** for mixed valid/invalid partitions.
3. **ListOffsets v0 emits valid offsets arrays.**
4. **ListOffsets v4+ returns the leader epoch for the returned offset**, not merely the current epoch.
5. **Fetch respects max bytes, partition max bytes, log start, high watermark, LSO, and leader-epoch fencing.**
6. **OffsetForLeaderEpoch returns Kafka-equivalent offsets and errors.**
7. **All participating storage engines maintain real leader epoch history.**
8. **Routed but unadvertised APIs are version-guarded.**
9. **API 23 remains unadvertised until client/differential proof exists.**
10. **Phase log, compatibility ledger, and audit entries are updated with exact verification output.**

The highest-value first patch is the ListOffsets replacement above. It directly addresses the known Phase 08 blocker and should eliminate the mixed-partition / produced-epoch wire decode failures before moving into Fetch and OFLE proof hardening.
